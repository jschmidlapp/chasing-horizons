# Architecture

```
src/content/        Markdown content (the data). Theme-agnostic; a future CMS edits these files.
  trips/<slug>/index.md (+ track.gpx)   one-off outings
  spots/<slug>/index.md (+ track.gpx)   places visited regularly
  regions/<slug>.md
  gear/<slug>.md
  pages/{home,places,gear}.md
src/content.config.ts   Zod schemas for the collections. This is the content contract.
src/data/media.json     Image manifest (dimensions + available widths), generated by media:process.
src/lib/                Theme-independent logic
  content.ts            Querying, sorting, region tree, URLs, excerpts (trips + spots = "entries")
  entry-page.ts         Props for a trip/spot page (linked entries, related, GPX track)
  media-core.mjs        "/media/<key>" → responsive R2 URLs (srcset), shared by components and Markdown
  rehype-media.mjs      Markdown plugin: responsive <img>, and image-only paragraphs → .gallery
  gpx.ts                Build-time GPX → simplified polyline + distance and elevation gain
src/theme/types.ts      The view contract (props for each view)
src/theme/starter/      The active theme: views/, components/, layouts/, styles/
src/pages/              Routes. Thin: load data via lib, render @theme/views/<View>.astro
scripts/import/         One-time Google Sites → Markdown importer (see migration.md)
scripts/media/          Image pipeline: add, process (sharp → WebP), r2 (upload/pull)
site.config.mjs         Site title, URLs, media base URL (env overrides)
```

## Routes

| URL | Page file | View |
| --- | --- | --- |
| `/` | `pages/index.astro` | `HomeView` |
| `/places/` | `pages/places/index.astro` | `PlacesView` |
| `/places/<region>/` | `pages/places/[region].astro` | `RegionView` |
| `/trips/` | `pages/trips/index.astro` | `EntryListView` (filter: `?activity=hike`) |
| `/trips/<slug>/` | `pages/trips/[slug].astro` | `EntryView` |
| `/spots/` | `pages/spots/index.astro` | `EntryListView` |
| `/spots/<slug>/` | `pages/spots/[slug].astro` | `EntryView` |
| `/gear/` | `pages/gear.astro` | `GearView` |
| 404 | `pages/404.astro` | `NotFoundView` |

All internal links go through `url()` / `entryUrl()` / `regionUrl()` / `listUrl()` in `src/lib/content.ts`, which add the deploy
base path (`/chasing-horizons` on GitHub Pages; `/` once a custom domain is in place).

## Rendering flow

1. Astro loads the collections (`content.config.ts`) and validates the frontmatter. A bad field fails the build.
2. A page in `src/pages` queries data through `src/lib/content.ts` and passes typed props to a view.
3. The Markdown body is rendered with the `unified()` processor plus `rehype-media`. Inline images become
   `srcset` images on R2. Consecutive image lines become a `.gallery` grid.
4. The theme's views lay everything out. `Lightbox.astro` makes body photos clickable.

## Markdown processor

Astro 7 defaults to its Rust Markdown engine (Sätteri). We explicitly use `unified()` from
`@astrojs/markdown-remark` (see `astro.config.mjs`) so we can run rehype plugins. If you add a remark or
rehype plugin, add it there.

## Static output

The site builds to plain static files in `dist/`. There is no server and no images, so the build is
about 2 MB. `npm run build` runs `astro check` (type-check plus content validation) first.
